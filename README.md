---

#### 1. Клонирование репозитория
* **Откройте терминал в папке с вашими сайтами Open Server и выполните:

* **git clone https://github.com/DnvMaster/Orvanta.git

---

#### 2. Установка зависимостей PHP
* **composer install
*  **npm run build

---

#### 3. Настройка окружения
* **Создайте файл .env и скопируйте весь код из файла .env.example и вставте в файл .env
* **Создайте базу данных в phpmyadmin
* **Укажите в созданном файле (.env) имя базы данных, тип соединения, хост, имя пользователя и пароль 

---

#### 4. Генерация ключа приложения
** *Выполните в консоле Open Server команду php artisan key:generate

#### 5. Накат миграций и наполнение базы
** *Выполните в консоле Open Server команду php artisan migrate

### Архитектура рассчитана на дальнейшее расширение CRM и подключение разграничения доступа во всех основных модулях.
* Добавлена модель Department для управления подразделениями компании.
* Добавлена возможность создавать иерархию подразделений через parent_id.
* Добавлена связь пользователя с подразделением через department_id.
* Добавлена связь пользователя с непосредственным руководителем через manager_id.
* Реализован механизм получения идентификаторов дочерних подразделений на всех уровнях вложенности.

## Система ролей
* Добавлена модель Role.
* Создана таблица roles.
* Добавлена возможность назначать пользователю несколько ролей.

## Подготовлены базовые роли:
* Администратор (admin);
* Руководитель (manager);
* Сотрудник (employee);
* Технический специалист (technical_specialist).
* Роли отделены от должностей сотрудников, что позволяет независимо управлять организационной структурой и правами доступа.

## Система разрешений
### Подготовлен каталог разрешений для основных разделов CRM:
* Сотрудники;
* Компании;
* Контакты;
* Сделки;
* Настройки;
* Аудит;

## Управление ролями и разрешениями.
### Области видимости данных
* own — доступ к собственным записям;
department — доступ к записям сотрудников своего подразделения и дочерних подразделений;
* all — доступ ко всем записям независимо от ответственного.
* Реализовано получение эффективной области доступа с приоритетом:
* all → department → own.
* Если у пользователя отсутствует соответствующее разрешение, область доступа не предоставляется.
